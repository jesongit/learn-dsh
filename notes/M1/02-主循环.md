> 备课出处（选读）：`deepseek-harness@53d1ef4a74` 的 `packages/agent-loop/src/loop.ts`（205 行主循环）、`packages/session/src/index.ts`（会话与投影）、`packages/llm/src/assembler.ts`（组装器）、`packages/tools/src/index.ts`（工具服务）。

## 本节目标

理解 loop 周围的三个新角色（会话日志、组装器、工具服务）如何协作，然后**亲手写出 agent 的心脏** `run_turn()`，并用 harness 场景 1 的行为规格验证它。

## 1. 三个新角色

- **Session（[session.py](../../src/pagent/session.py)）**：只追加的事件日志，第 0 课「模型可见即已记录」原则的落地。append 永不阻塞；**模型历史是日志的投影**，不是第二份列表。
- **BlockAssembler（[assembler.py](../../src/pagent/assembler.py)）**：把 chunk 增量流拼回完整块。BlockEnd 给的完整块优先，没给就按增量拼；没等到 finish 就当 stop。
- **ToolService（[tools.py](../../src/pagent/tools.py)）**：注册「名字→实现」，按名执行；**工具炸了不炸 loop**——错误也变成 ToolOutcome 回填给模型，让它自己调整。

### 投影规则（derive_messages，务必吃透）

| 日志事件 | 投影成 | 说明 |
|---|---|---|
| `user/message` | user 消息 | 用户真说的话 |
| `assistant/message` | assistant 消息 | **组装完的**才是历史 |
| `assistant/chunk` | **不投影** | 回放/UI 数据，只落日志 |
| `tool/result` | **user 消息 + tool-result 内容块** | 词汇表没有 tool 角色！ |
| `context/message` / `steering/message` | 带信封的合成 user 消息 | `<context>…</context>`（M1-03 用） |

最反直觉的是最后一行前的两行：**工具结果骑在 user 消息里回填**（OpenAI/Anthropic 系工具回传的通用形态），**chunk 不进历史**（进历史的资格只属于组装完的消息）。

**两个「为什么」（展开最反直觉的两行）**：

- 工具结果归 user：assistant = 模型说出去的，user = 外界喂进来的；工具结果是外界喂的信息，与用户输入同类。至于它在各家 wire format 里长什么样（OpenAI 的 `role:"tool"`、Anthropic 的 user 内 tool_result 块），是 adapter 的翻译活，词汇表保持中立。
- chunk 不进历史：历史记「说了什么」，不记「怎么说的」——类比 git 存 commit、不存编辑器按键。chunk 落日志是为回放与 UI（M2 逐字渲染要用）。

### 投影的两个维度：取哪些 vs 取多少

- **取哪些**（类型过滤）：上表规则，永远不变。
- **取多少**（时间范围）：v0 = **全量，不按轮次裁**。LLM API 无状态，「多轮记忆」全靠每次把完整历史带上——日志里有两轮就投影两轮，只取最新一轮模型就失忆了。
- 上下文超限要砍旧内容时，那是**压缩（compaction）**——M4 的主题。做法不是投影时随手裁，而是压缩动作本身落日志（摘要标记），投影规则加一条「标记后的旧消息用摘要代替」——「模型可见即已记录」依然成立。

### derive_messages 在哪、怎么用

- 定义：[session.py:68](../../src/pagent/session.py#L68)（30 行，读一遍）——「投影」的具体实现就是它。
- 用法：loop 每次组装请求时现场调用（[loop.py:54](../../src/pagent/loop.py#L54)）——不存在「维护第二份消息列表」；落日志越勤投影越新，漏落日志投影就缺。
- 它还是**隐性检验器**：TODO(7) 若漏落 tool/result，第二次 `derive_messages()` 就少一条，mock 收到的请求不完整，测试规格第 6 条当场抓住。

## 2. 一个 turn 的时序

```mermaid
%%{init: {"fontFamily": "Microsoft YaHei"}}%%
sequenceDiagram
    participant U as 测试/用户
    participant L as run_turn（loop）
    participant S as Session 日志
    participant M as MockAdapter
    participant T as ToolService
    U->>L: agent.send("hi")
    L->>S: user/message + turn/start
    loop 每个 step
        L->>S: step/start
        L->>M: stream(请求 = derive_messages() 投影)
        M-->>L: chunk × N（流式返回）
        L->>S: assistant/chunk × N（先落日志，再喂组装器）
        L->>S: assistant/message（组装完的才进投影）
        L->>T: execute(工具调用)
        T-->>L: ToolOutcome
        L->>S: tool/result（user 角色 + 结果块）
        L->>S: step/end
    end
    L->>S: turn/end
```

图例：**实线 `->>` = 主动调用，虚线 `-->>` = 返回**。注意一个事实：日志的每一笔都由 loop 写入——模型和工具只把结果**返回给 loop**，从不直接碰日志（对应 TODO(5)(7) 里"先记返回值、再落日志"的顺序）。

### 3.1 loop 主流程伪代码（原文件头逐行注释版）

原文件里这整块就是 loop.ts 顶部的注释——开发者把执行顺序当文档放在实现正上方。下面去掉注释符号、逐行标注，右列对照你要写的 PAgent 代码：

```text
forever:                                # 外层循环 = agent 的一生
  wait for queued messages (idle)       # 空闲挂起等新消息（v0 简化：排空即返回，M2 归还）
  TURN: drain queued                    # 取走 inbox 全部排队消息            → TODO(2)
        session('turn/start')           # 开轮落日志                         → TODO(3)
  STEP loop:                            # 内层 = 一个 turn 里的 step 循环
    session('step/start')               # step 开张                          → TODO(4)
    assembly = 汇总(系统提示词,          # 「我给你什么上下文、你能调什么工具」
               工具说明书)              #   v0 拆两处：agent.system_prompt + tools.schemas()
    req = { model,                      # ── 组装请求 ──
            system:   assembly.提示词,   #   assembly 产物①：系统提示词
            messages: deriveMessages(), #   历史 = 日志投影（现算，不存储）
            tools:    assembly.工具清单 }#   assembly 产物②：告诉模型能调哪些工具
    stream llm.stream(req) →            # ── 发请求，流式收 chunk ──
      每个 chunk: 先 session('assistant/chunk') 落日志，
                  再 assembler.push(chunk) 组装
                                        #                                    → TODO(5) 铁律①
    assistant = assembler.message()     # chunk 拼成完整消息
    # ★ tool_calls 从这里来：模型在 assistant.content 里「说」它想调什么工具
    tool_calls = assistant 中所有 ToolCallBlock
    session('assistant/message')        # 完整消息落日志（只有它进投影）      → TODO(6)
    each call in tool_calls:            # ── 逐个兑现模型点的菜 ──
      session('tool/call')              #   调用前落日志                     → TODO(7)
      tools.execute(call)               #   执行（炸了也回错误结果，不炸 loop）
      session('tool/result')            #   结果落日志（user 角色+结果块）    → TODO(7)
    cont = hadToolCalls || steered      # 方向盘：调过工具（或被插话）就继续  → TODO(9)；steered 属 M1-03
  session('turn/end')                   # 关轮                              → TODO(10)
  await parallel('session/flush')       # 等日志刷盘 = 持久化检查点（M6 讲）
```

注意两个顺序铁律：**chunk 先落日志再喂组装器**（记账优先）；**请求用 deriveMessages() 现场投影**（不存在"手里攒一份消息列表"这种东西）。

## 7. TS vs Python 差异与坑

- `Date.now()` ↔ `int(time.time() * 1000)`（毫秒要自己乘）。
- harness 的 `readonly SessionEvent[]` 只是不让改引用；我们直接返回内部 list 的引用——v0 接受（写坏日志的唯一入口是 append，自律）。
- `switch (event.type)` ↔ `if/elif event.type ==`——语义等价，Python 没有 fall-through 负担。
- async generator 的「调用即返回」在 loop 里无处不在：`agent.llm.stream(request)` 返回的是生成器，`async for` 才开始跑（M1-01 已踩过）。

## 附：Cordis 思想的 Python 落地对照（M0 伏笔的兑现）

「不复刻框架形态，用 Python 重写它承载的思想」。Cordis 的服务容器/事件总线/生命周期三样里，只有前两者承载的**思想**值得带进 PAgent；最后一个（HMR/fiber）是 50+ 包互相插拔才需要的重型机制，学习项目彻底不要。

| Cordis 提供 | dsh 用法 | PAgent 的对应物 | 状态 |
|---|---|---|---|
| ctx 服务容器 | `ctx.tools` / `ctx.llm` / `ctx.sessions` | 普通对象当字段传：`agent.tools` / `agent.llm` / `agent.session` | ✅ M1 |
| 注册是可逆副作用 | `ctx.effect(fn)` 装卸 | dict 注册表 + `register()`（v0 不需要可逆） | ✅ M1 |
| 类型化事件总线（waterfall/parallel/…） | 拦截请求/工具/轮次 | 监听器列表（朴素版） | ⏳ M3 |
| 生命周期 / HMR / fiber | 热重载、插件装卸 | 彻底不实现 | ❌ 永不复刻 |
| 声明合并扩展词汇 | 插件加内容块类型 | 加 ContentBlock 子类 | ❌ 永不复刻 |

两个对应的反面教材：工具 if-else 硬编码在 loop 里（对照 `ToolService.register` 的注册表）；审批/审计需求直接改 `run_turn` 本体（对照 M3 的事件监听）。检验标准：**删掉 Cordis，dsh 的 loop 一行不用改也能跑**——loop 只依赖「有一个能注册的地方」，不依赖那个地方是谁。

## 9. 小结与遗留问题

- 会话日志是唯一真相；模型历史 = 投影；chunk 只进日志不进历史。
- 投影两维度：取哪些 = 类型规则（本节）；取多少 = 全量（LLM 无状态）；截断属 M4 压缩，压缩也落日志。
- 工具结果骑 user 消息回填；工具炸了回错误结果而不是抛出。
- loop 的决策只有一个：本 step 有没有工具调用（M1-03 加 steering）。
- Cordis → PAgent：注册表已有，事件总线 M3 建，框架形态永不复刻。
- 遗留问题：无。
