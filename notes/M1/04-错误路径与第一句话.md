# M1 · 第 4 节 · 错误路径与第一句话

> 备课出处（选读）：`deepseek-harness@53d1ef4a74` 的 `packages/agent-loop/src/loop.ts`（runStep 异常 → error 事件 → reason=error）、`examples/echo-agent/src/mock-llm.ts`（规则式假模型）与 `examples/echo-agent/src/stdio-chat.ts`（终端对话雏形）。

## 本节目标

补上 turn 的第三种结束方式（模型错误），给循环装上防跑飞闸（max_steps），然后——**亲手点**：第一次 `uv run`，在终端里和自己的 agent 对话。

## 1. turn 的三种结束原因（本节补齐第三种）

| reason | 何时发生 | 谁的锅 |
|---|---|---|
| `completed` | 模型不欠工作了（或插话已消化） | 正常 |
| `error` | **模型/adapter 本身炸了**（本节新增） | 基础设施级失败 |
| `max-steps` | 达到 step 上限被截断（**PAgent 自加**：harness loop 未内置，为什么见 §3） | 保护闸 |

关键区分（M1-02 讨论过的"错误当数据"在这里画出边界）：

- **工具失败 = 数据**：is_error 结果回给模型，turn 继续——模型能自行处理；
- **模型失败 = turn 级事故**：连"下一句话"都产不出来，本轮只能以 error 收场，异常必须在 loop 内部消化（不能炸到调用方）。

## 2. 错误路径的顺序（harness 提炼）

```text
try:                                     # ← step 主体（组装→流式→工具）包进 try
    组装请求 / 流式收 chunk / 工具往返
except Exception as e:
    error = str(e)                       # ← 记下，不在这里 break
# 错误时下面照常执行——日志叙事要完整：
排插话 → steering/message → step/end
if error is not None:
    session.append("error", {turn, step, message})   # ← 落 error 事件
    break
方向盘 …
session.append("turn/end", {reason: "error" if error else …})  # ← 带原因关轮
```

三个易错点：① try 的范围是 step 主体，**不含**排水/step/end（它们必须永远执行）；② `error` 事件在 `step/end` **之后**；③ break 后仍要走 `turn/end`（reason=error）——turn 无论怎么死都要合上。

## 3. max_steps：防跑飞闸

**为什么 harness 没有**：它的 loop 敢于「裸奔」，因为外面有三层保障——① 真实模型有结束倾向，调完工具就会总结，无限循环极罕见；② 用户随时 abort/dispose（M2 讲）；③ 超时与预算放在**外围守卫层**（harness 的 guard 包，见待探索清单）统一管理。设计哲学：**loop 保持薄，限制集中在守卫层**——策略可配置、可组合，不焊死在循环里。

**为什么 PAgent 要有**：你马上写的 EchoAdapter 是规则式假模型——if 条件错一个就是永动机；规则式不排剧本，没有「脚本耗尽」这个天然终止兜底；demo 还要亲手在终端跑，不能靠 Ctrl+C 保命。附带一个小收获：reason 枚举因此多出 `max-steps`（harness 四种 → 我们五种）——「可扩展词汇」的第一次实际扩展。

**通用原理 vs 工程选型**：「防跑飞」是通用原理，任何 agent 都需要；「闸放 loop 内还是守卫层」是选型——学习项目选内置（简单直接，顺手扩展 reason），harness 选守卫层（生产级可组合）。两者不冲突；如果日后给 PAgent 做守卫层，这道闸可以搬出去。

## 4. echo demo：规则式假模型（亲手点①）

第三种 mock 风格（M1-01 预告过）：**不排剧本，按规则现场算响应**——输入 `echo xxx` 就发工具调用，看到 tool-result 就收尾，否则正常接话。它能对任意输入反应，所以能撑起一个终端对话。实现要点：**末条用户文本要倒序找**——投影全量累积，多轮对话后 messages 里有多个 user 消息（每轮输入都留在日志里），最新的在最后面；正序首个是**最早**那句旧指令，倒序首个才是**最新**输入。

跑法：`uv run python demos/echo.py`。已备好：echo 工具、终端流式回显（`TerminalUI` 装饰器——seam 叠 seam，UI 只是旁听 chunk 流）、主循环。你写 [demos/echo.py](../../demos/echo.py) 里的 `EchoAdapter`（TODO(A)~(C)，docstring 里有完整提示）。

**亲手点流程**：写完 EchoAdapter → 亲手 `uv run python demos/echo.py` → 随便聊一句 → `echo 你好` 看完整工具往返 → **把 `max_steps=8` 改成 1** 再跑 `echo 你好`，亲眼看循环被截断（输出会停在半路，reason=max-steps）→ 改回 8。

## 8. TS vs Python 差异与坑

- TS 的 `AbortSignal` 让错误路径要区分 aborted/error 两类；v0 没有中断，只有 error（M2 加）。
- urllib 是同步的，冒烟脚本里用 `asyncio.run` 包 async adapter——真实 M2 适配器会换 httpx 的异步客户端。
- `except Exception` 在 Python 里不接 `KeyboardInterrupt`（它继承 BaseException）——Ctrl+C 永远能打断，这是语言送的善意，M2 讲中断时是主角。
