## 本节目标

mock 全面退役：终端 demo 换上 DeepSeekAdapter 真聊，steering 在真模型上实测。**M2 验收三件事——流式对话、可中断、可插话——在本节合龙。**

## 1. 一句话理解

**换真模型 = 注册表里换一个 adapter + agent 换个模型名——代码一行逻辑不改，改的是"接线"。本节的工作量在验证，不在编码。**

## 2. 概念讲解

### 2.1 接线：一行切换

```python
from pagent.deepseek import DeepSeekAdapter
llm.register(["deepseek-chat"], DeepSeekAdapter(api_key=api_key))   # 新 adapter 上岗
agent = Agent(..., model="deepseek-chat")                            # 模型名指过去
```

EchoAdapter 和 MockAdapter 不删（它们还是测试基建），只是 demo 不再用。这就是 M1-01 以来整条 seam 链条的兑现时刻：**换模型是改注册表，不是改代码**。

### 2.2 真模型带来的第一个真问题：测试怎么办？

真模型不可预排——`MockAdapter` 的剧本和 `EchoAdapter` 的规则在这里双双失效。解法是**分层**（测试金字塔在 agent 上的落法）：

| 层 | 用什么模型 | 测什么 |
|---|---|---|
| 单元测试 | mock（剧本/规则/hang） | loop 语义、投影、中断收场——确定性断言 |
| 冒烟/集成 | 真模型 | 接口形状、真实 SSE 解析、端到端能跑 |
| 人工验收 | 真模型 | 流式体验、插话效果——"像不像个 agent" |

**单测永远不进真模型**（慢、花钱、不可复现）；真模型的验收靠冒烟 + 人工清单。这不是妥协，是行业通用分层。

### 2.3 第二个真问题：工具往返在 M2 还是残缺的（M3 伏笔）

M2-01 遗留过：`_build_body` 只会拼 TextBlock——**真模型若调用工具，Round 2 的工具结果会被投影丢掉，模型看不到结果**（M3 补 tool 消息的 wire format）。所以本节 demo **不注册工具**（纯对话），你甚至会故意观察到一次"模型反复调工具"的怪象（若注册了的话）——把它记下来，M3 见分晓。

### 2.4 steering 实测：插话效果的验收

真模型的插话效果不可预排，但**可观察**：中途插"只要前 3 条"，看它后续输出是否转向。验收标准是行为级的（改道了没有），不是断言级的。demo runner 需要一条 `/steer` 命令把输入转给 `agent.steer()`——这是本节唯一的编码点。

<a id="lesson-log"></a>
### 实录（节收尾补记）

- 用户实现 TODO(G)(H) 完成后，验收中发现**两个真问题并修复**（都在 runner，根因教学价值高于现象）：
  1. **`/stop`、`/steer` 永远打不中**：旧 runner 等 turn 结束才回到 `input()`——流式期间根本没有输入通道。修法：**并发输入**——后台线程读键盘 → `asyncio.run_coroutine_threadsafe` 桥接进队列 → 主循环 `queue.get()` 分发命令。这不是打字手速问题，是**架构缺一个常驻输入通道**（Web 里这个问题天然不存在——浏览器请求本来就是并发的，正是 harness 做 Web 的原因之一）。
  2. **回复太快，窗口打不开**：`TerminalUI` 增加 `delay` 参数（每 chunk 停 50ms）——降速也是一层包装，**seam 叠 seam 实战**。
- 首条消息越界崩溃（`events[-1]` 空列表）：真模型有秒级延迟，mock 时代从未暴露的竞态——集成课的「实战税」。
- `reason=error` 排查实战：`[错误详情] None`（`str(KeyError(None)) == "None"`）→ 自建诊断脚本抓真实 traceback → 根因是**样例数据不忠实**（真实流每帧都带 `finish_reason:null`，理想化样例让单测假绿）。教训已入 [M2-01 实录](01-真实适配器.md#lesson-log)：**样例数据要采样自真实 wire**。

<a id="qa-seam-stack"></a>
### 对话疑点：seam 叠 seam 是什么？

同一个接缝，**叠多层实现**：外层转发给内层并夹带私货，调用方只认接口、不知道自己被包了几层。demo 里的 `TerminalUI(EchoAdapter())` / `TerminalUI(DeepSeekAdapter(...))` 就是两层——UI 旁听 chunk 流（打印/降速）后原样转发。软件工程的老熟人：**装饰器模式 / middleware 洋葱模型 / Unix 管道**（每段同接口所以能无限串）；M1-02 的 waterfall 是同一思想用在**事件**上，叠 seam 是用在**服务**上。威力在组合：`Logging(Retry(DeepSeekAdapter()))` 随时包一层，loop 与真 adapter 毫不知情——harness 的 `packages/llm/llm-retry` 就是同一物种。
